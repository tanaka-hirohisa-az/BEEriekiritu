## 加工した点（これ以外は一切していない）

1. CHAR型の前後空白を除去（CHAR固定長のパディング）
2. タブ・CR・LFを半角スペースに置換（CSVの行が壊れるため。該当は売上実績の品目コード1件のみ）
3. DATE型を `YYYY/MM/DD HH24:MI:SS` の文字列で出力
4. NUMBER型を指数表記にならないよう固定小数で出力し、末尾の余分なピリオドを除去

## 結合するときに踏むと危ない点

**売上実績のキーは `F_在庫品目番号`、単価マスタのキーは `F_納入品目番号` で、この2つは一致しない場合がある。**
`04_TB_納入品目情報.csv` が両方を持つので、これを介して変換する。74,755行のうち 8,136行で両者が異なる（DB上の件数も 8,136）。

2025年以降に売上のある「品目×得意先」9,140組のうち、単価マスタ(02)に該当があるのは 9,060組（99.1%）。内訳は在庫品目番号経由で 9,044組、納入品目番号での直接結合で 8,998組。**どちらか一方だけでは取りこぼす**ので、両方でフォールバックさせる。

※ この組数はCSV上で数えた値。前回READMEの値（8,889組中 8,810 / 8,794 / 8,749）はDB上で数えたもので、前回CSVで数え直すと 8,811 / 8,795 / 8,750 と1組多くなる。改行混入品目 `3WMX76112-100` がCSVでは改行除去済みのため単価マスタと一致するのが理由。

ある売上日時点の登録単価は、その品目×得意先で `F_開始日 <= 売上日` を満たす最新の開始日のレコード。
